# 연구소 워커

ERP의 **연구소**(`/lab`)에서 맡긴 일을 가져와 이 맥에서 Claude 로 처리하고, 결과를 보드에 돌려놓는다.

```
폰·PC 브라우저 → ERP 팝업에 지시 → lab_tasks 에 'queued'
                                        ↓  워커가 3초마다 집어 간다
                              맥에서 claude -p 실행 (연구원별 모델·도구)
                                        ↓  결과를 적는다
                                 보드의 '확인 대기' 칸
```

맥이 꺼져 있으면 지시는 쌓여 있다가 켤 때 처리된다. 켜져 있던 중 끊긴 일은 워커가 다시 켜질 때 `맡긴 일`로 되돌린다.

## 준비

**남은 건 하나뿐이다 — Claude Code CLI 로그인.**

```bash
claude auth login
```

데스크톱 앱에 로그인돼 있어도 CLI 는 따로 로그인해야 한다(앱과 자격 증명을 나눠 갖지 않는다).
로그인하면 구독 계정으로 돌아가 API 요금이 따로 나가지 않는다. 로그인 전에는 워커가 일을
집어 가지 않고 기다리므로, 먼저 켜 두어도 지시가 실패로 적히지 않는다.

### 이미 돼 있는 것

| 무엇 | 어디 |
| --- | --- |
| 설정 파일 (권한 600) | `~/.config/lab-worker/config.json` |
| 작업 폴더 | `~/연구소작업/` (연구원마다 그 아래 자기 폴더) |
| 워커 전용 비밀값 | 해시만 `private.app_secrets` 의 `name='lab_worker'` |
| 자동 시작 파일 | `~/Library/LaunchAgents/com.work-erp.lab-worker.plist` (아직 올리지 않음) |

비밀값은 **`CRON_SECRET` 과 다른 값**이다. 워커 쪽이 새더라도 연구소 함수만 열리고 크론
함수(캘린더·백업·공고)는 그대로 잠겨 있게 하려고 따로 만들었다. 바꾸려면 새 임의 문자열(32자 이상)을
만들어 설정 파일에 넣고, 그 sha256 을 `private.app_secrets` 의 `lab_worker` 행에 넣으면 된다.

### 돌리기

```bash
node tools/lab-worker/worker.mjs
```

맥을 켜면 저절로 돌게 하려면:

```bash
launchctl load ~/Library/LaunchAgents/com.work-erp.lab-worker.plist
```

멈추려면 `launchctl unload` 로 같은 파일을 내린다. 기록은 `~/Library/Logs/lab-worker.log`.

## 비용

추가 과금은 꺼져 있다(`extraUsage: disabled`). 한도를 넘으면 요금이 붙는 게 아니라 멈춘다.
쓰는 것은 Max 플랜의 한도이고, 쓰는 때는 **일을 맡겼을 때뿐**이다.

- **쉬는 동안 Claude 는 0.** 3초마다 Supabase 에 "할 일 있어?" 묻는 작은 요청만 보낸다
  (하루 2만 8천 번 × 수백 바이트 ≈ 14MB). 간격을 늘려 기다리게 할 이유가 없다.
- **건별로 얼마나 썼는지**는 결과 끝에 붙는다 — `— 입력 12.3k · 출력 450 · 23초`.
  전체 한도는 Claude 앱의 사용량 카드에서 본다(워커가 쓴 것도 같은 계정·같은 한도라 거기 합산된다).
- **한 건에 15분 제한**, **하루 40건 제한**(`plan.mjs` 의 `DAILY_LIMIT`). 한꺼번에 한도를
  쓰지 않게 막아 둔 것이고, 숫자는 거기서 바꾼다.
- 수집·분류는 haiku, 양식 있는 문서는 sonnet 으로 내려 둔 것도 같은 이유다.

## 안전하게 둔 것

- **Bash 는 아무에게도 주지 않는다.** 웹에서 들어온 문장을 맥에서 돌리는 구조라 처음에는 좁게 둔다. 필요해지면 `plan.mjs` 에서 연구원 하나씩 넓힌다.
- **연구원은 자기 작업 폴더 안에서만 돈다** (`cwd` 를 그 폴더로 두고 `--add-dir` 를 주지 않는다). 폴더 이름은 영문·숫자만 받아 경로를 벗어나지 못한다.
- **service_role 키를 쓰지 않는다.** `CRON_SECRET` 으로 잠근 DB 함수(`cron_lab_*`)로만 닿는다. 공개 키(`publishableKey`)는 노출돼도 되는 값이고, 그것만으로는 아무것도 못 읽는다.
- **한 건에 15분**이 넘으면 끊고 '시간이 넘었다'를 결과로 적는다.
- 지시를 넣을 수 있는 사람은 RLS 때문에 본인뿐이다.

## 쉴 때 하는 일 — 공고 요약 적체 풀기

맡긴 일이 하나도 없을 때, 워커는 ERP 에 "요약 안 된 원가 공고 한 건만 요약해 달라"고 부탁한다.

```
워커 → POST /api/lab/summarize  (워커 전용 비밀값으로 확인)
         ↓  서버가 한 건만: 나라장터 첨부 내려받기 → 한글/PDF 읽기 → 요약
       { done: 1, remaining: 36 }
         ↓  남은 게 있으면 워커가 바로 다시 부른다
       남은 0 → 6시간 쉰다
```

**왜 이렇게 나눴나.** 요약 1건은 길면 230초 걸리고 Vercel 함수는 300초에서 끊긴다. 그래서
아침 크론(`bid-digest`)은 하루 한 건밖에 못 하고, 사람이 봐야 하는 공고 42건 중 5건만
요약이 있었다. 시간 제한이 없는 쪽(맥)이 반복을 맡고, 파일과 API 키를 가진 쪽(서버)이
요약 한 건을 맡는다.

**순서와 상한.** 보드에 맡긴 일이 늘 먼저다. 요약은 할 일이 없을 때만 하고, 하루
`SUMMARY_DAILY_LIMIT`(20)건까지만 한다 — 요약 1건마다 서버의 `ANTHROPIC_API_KEY` 로
실제 돈이 나가기 때문이다(워커가 부르는 `claude -p` 와 달리 구독 한도가 아니다).

`appUrl` 을 설정에 넣지 않으면 `plan.mjs` 의 `APP_URL_DEFAULT` 를 쓴다.

## 연구원이 쓰는 스킬

연구원마다 `Skill` 도구가 열려 있어서, 계정에 붙어 있는 스킬(`cost-bid-pricing`,
`cost-quote-and-kickoff`, `meeting-minutes-ddd` …)을 그대로 쓸 수 있다. 연구원 폴더에서도
스킬이 보이는 것은 실측으로 확인했다. 지시에 스킬 이름을 적어 주면 더 확실하다.

```
원가 연구원에게:
  이 공고의 투찰가를 추천해 줘. cost-bid-pricing 스킬을 써.
  공고번호 20261100123-00, 제목 "○○시 원가계산 용역"
```

도구를 늘려도 입력 토큰은 거의 안 늘어난다 — 도구 1개와 6개 차이가 9토큰이었다.
